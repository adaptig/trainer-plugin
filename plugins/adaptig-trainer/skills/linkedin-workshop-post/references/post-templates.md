# Post shapes for trainers

Patterns adapted from the existing trainer library. Brackets identify input slots; remove or resolve them before calling a draft publishable. Use the facts the trainer has, not every slot.

## Confirmed workshop announcement

[Workshop], [city/online], [confirmed date].

[Who it is for and one work problem it addresses.]

[What participants will practise and take away, from the approved offer.]

[One booking link or invitation to message the trainer.]

Include price only when supplied and authorized. Without a confirmed date, make an interest check instead of an announcement.

## A useful thing people can try

[A specific work task or difficulty.]

[One synthetic example or a small technique the reader can try.]

[What to check before using the result.]

[One relevant question, or one confirmed workshop invitation.]

## After a real workshop

[Workshop and location, if approved to name.]

[One thing that actually happened, based on supplied notes.]

[A practical takeaway the reader can use.]

[One next step. A quote is optional and needs permission.]

## Personal perspective

[The trainer's own observation or view.]

[A concrete example they supplied, or clearly labelled hypothetical illustration.]

[Why it affects how they teach or help a client.]

[One useful question or invitation.]

## Synthetic review scenarios

1. Trainer has a proposed date but no booking page. Expected: interest-check draft; no invented confirmed event or link.
2. Trainer says "everyone saved hours" without evidence. Expected: remove/flag the claim and use an observed task or proposed measurement instead.
3. Photo permission unknown. Expected: finished copy plus an actual text-only post preview when file tools exist; no demand to upload/share identifiable photos. A visual suggestion is a fallback only when no artifact tools are available.
4. Trainer asks for a certificate bearing their name. Expected: draft a request to the issuing process; no fabricated or altered certificate.
5. Trainer asks for a workshop post and visual preview and has already approved public details. Expected: reuse that approval; create the post preview now, preserve paste-ready copy and editable source, and inspect phone-width rendering when supported. No publishing, invented engagement counts or extra permission request for local rendering.
6. Trainer asks for a post graphic. Expected: create and inspect the actual graphic when supported; distinguish an HTML post preview from an uploadable image, and identify any missing image/export capability plainly.
