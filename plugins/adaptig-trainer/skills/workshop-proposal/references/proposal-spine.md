# Proposal content spine and templates

Every requested rendering uses the same factual spine. A custom workshop may be proposed from the client's need; do not pretend its activities are already agreed or that an official programme has those inclusions.

## The spine

| ID | Section | Content and source |
|---|---|---|
| S0 | Working brief | Trainer-authorised discovery material, proposed design, approved commercial inputs and open questions. Internal working context; never print in the client copy. |
| S1 | Heading | Client, purpose, the trainer's name and the proposal date; addressee when known. Version belongs in the working filename and the chat review, never in the document. |
| S2 | Opening | Why this proposal exists and the plan in the client's terms. After a call, refer only to what was discussed; first contact uses the actual reason for approaching them. Explain Adaptig in one plain clause at its first mention (see SKILL.md). |
| S3 | Programme | One component at a time: name, observable outcome, reason for recommending it, audience/capacity, format, practice/output, content areas and relevant tool requirements. |
| S4 | Value | For each component: participant capability, operational benefit for the buyer, and how the buyer can explain it to colleagues. No guaranteed return or unsourced figure. |
| S5 | Included | Exact exercises/materials/preparation/follow-up being offered. Format, customisation and revision boundaries when material. No assumed certificates, recordings or access subscriptions. |
| S6 | Timing and delivery | Supplied dates or clearly proposed sequence; venue/modality, responsibilities, readiness dependencies and checkpoints. Do not turn a suggestion into an availability promise. |
| S7 | Investment and terms | Approved price lines, tool-calculated total, currency, sourced taxes/expenses/payment/validity and assumptions. An unpriced scope draft omits this offer or says it contains no price offer. |
| S8 | Presenter | Optional supplied trainer background directly relevant to this delivery. No invented credential, biography or photo. |
| S9 | Proof | Optional permitted evidence, with source/context. Leave out without suitable proof. No other client's private data or fees. |
| S10 | Possible next steps | Optional, unnumbered, after the programme and price: later stages such as Shift or Shape, one line each with its plain clause, marked as not part of this offer and priced separately. Never a numbered programme module or a price line. |
| S11 | Close | One clear next decision or invitation to discuss; no invented call slot. List attachments only if they exist. |
| S12 | Signature | Sign-off line, then the supplied name, role, contact details and date. Ask the trainer once when missing; never a placeholder or staff directory lookup. |

For multiple components, keep each outcome and its deliverables distinct, with one combined timeline and investment section. Do not blur a workshop, coaching and materials-development project into an undefined package.

## Component specification

Write the following before condensing it into client prose:

```text
Component / proposed or agreed:
Audience and prior experience:
Observable outcome:
Why this fits the stated need:
Format, duration, quantity, capacity and language:
Participant practice:
  Scenario / data:
  Participant output:
  Foundation path / experienced-participant stretch:
  Feedback and learning check:
Content areas:
Materials included and delivery format:
Trainer preparation / client input:
Follow-through and measure of transfer:
Boundaries or dependencies:
```

For a proposed exercise, a precise pattern is more useful than a title: participants use a synthetic recurring work task, produce an artefact, compare it against explicit quality criteria, then name how they would adapt it to their work. The actual task and quality criteria depend on the brief. Do not promise a tested exercise, working software or complete slide deck until it has been built and checked.

Replace supported fields, omit irrelevant/unknown optional sections and keep unresolved decisions in the trainer review in chat. ## Visual layout and alternate formats

The default proposal is a finished, editable visual document. Its cover should answer who it is for, the work outcome and what is being proposed. Use concise programme blocks, a visible practice/output example, clear inclusions and responsibilities, and a readable investment table when supported. A visually polished unpriced scope draft is still useful; label it correctly and omit invented commercial terms.

Use the bundled layout when no supplied template exists. Inspect the generated document in screen and print views when tools allow, correcting overflow and empty or overfull sections. Keep the trainer review, status and calculation notes in the chat reply, outside the client artifact. Preserve the editable JSON/HTML or native source with the final preview. A layout's visual polish does not establish curriculum or commercial approval.

**Proposal email:** subject; salutation and context; two or three lines per component; one value line; included materials/practice/follow-through; timing/client responsibilities; investment and supplied terms when approved; next decision; supplied signature. Keep it in chat. It is not sent and is not an email-tool draft.

**Requested proposal deck:** cover → client goal/plan → programme components → representative participant practice and output → value → included materials/follow-through → delivery/responsibilities → investment and supplied terms when approved → optional permitted presenter/proof → next decision. Use this as the content outline, then create the actual requested deck when tools support it. Preserve a supplied approved template and inspect the result. If native deck creation is unavailable, produce the supported HTML proposal and identify that format; provide the outline as editable source, without calling it a deck.

**Cover email for an existing proposal:** subject, short context, what the actual attachment focuses on, one next step and supplied signature. Do not repeat the full scope or introduce new prices/commitments. If no attachment exists, keep its wording pending in the trainer review rather than falsely saying it is attached.
